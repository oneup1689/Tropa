# iOS, этап 2: запись трека на iOS (план, код не писался)

Статус: черновик плана от 2026-10-16. Начинать только после того, как этап 1 (`Tropa.ipa` через SideStore) запустился на iPhone
и владелец согласовал план. Решения, отмеченные «(мой выбор)», владелец может поменять.

## 1. Что есть сейчас (по коду)

На iOS запись идёт в Dart: `Recorder._startDart` (`lib/recorder.dart`) слушает `Geolocator.getPositionStream` с
`AppleSettings(accuracy: best, activityType: fitness, distanceFilter: 3, allowBackgroundLocationUpdates: true,
pauseLocationUpdatesAutomatically: false, showBackgroundLocationIndicator: true)` и пишет точки в SQLite.
`Info.plist` уже содержит `UIBackgroundModes=location` и тексты запросов.

Чего на iOS нет (в коде везде `Platform.isAndroid`):

| Что | Где на Android | Нужно ли на iOS |
|---|---|---|
| Фильтры качества точек (скачок скорости, доплер, первая точка после потери) | `TrackingService.kt` | Да, иначе трек хуже Android |
| Автопауза (стоим на месте) | `TrackingService.kt` | Да |
| Ручная пауза / продолжить | `pause()/resume()` | Да |
| Цель по дистанции + уведомления | `checkGoal()`, `Notifier.kt` | Желательно |
| Режимы пешком/вело/авто (профили `modes.dart`) | передаются в службу | Да, профили уже в Dart |
| Восстановление после выгрузки приложения | служба START_STICKY | Частично (см. риски) |
| Экран «готовность» (GPS, доступ, уведомления) | `readiness.dart` | Да, свой набор проверок |
| Навигатор: голос, звук, вибро | `Speaker.kt`, `Sounds.kt` | Этап 3 |
| Автозапись 24/7, «ждать у старта» | служба + шаги | Этап 3 / позже |
| Компас («Где я») | `CompassStream.kt` | Этап 3 (у geolocator есть heading) |

## 2. Главный выбор: где писать запись

**Вариант A (мой выбор): оставить запись в Dart, довести её до уровня Android.**
Фильтры, автопауза, пауза, цель переносятся в чистые Dart-функции с юнит-тестами (их можно гонять на Windows без iPhone).
Фоновая работа держится на режиме `location` (приложение не засыпает, пока идёт запись).
Плюсы: один код на две платформы, тесты на ПК, быстрые итерации через GitHub Actions.
Минусы: если система выгрузит приложение (мало памяти), запись оборвётся, пока человек не откроет приложение.

**Вариант B: нативная Swift-служба на `CLLocationManager`, пишущая в SQLite сама** (как Kotlin на Android).
Плюсы: переживает закрытие интерфейса. Минусы: много нативного кода без возможности отладки на Windows
(нет симулятора, каждая правка — сборка 5–10 минут и тест на телефоне).

Рекомендация: A, затем одна реальная прогулка с логом. Если в логе будут дыры из-за выгрузки приложения — переходим к B
(или к «значимым изменениям местоположения» для перезапуска приложения системой).

## 3. Состав работ (A)

1. **Общий движок фильтров на Dart** (`track_filter.dart`): профили режимов из `modes.dart`, отбрасывание по точности,
   скачок скорости с проверкой по доплеру (`Position.speed`/`speedAccuracy`), потеря сигнала, «телепорт» не даёт дистанцию.
   Тесты на синтетических треках и на `test/tropa_*.gpx` (личные, в Git не идут).
2. **Автопауза** на iOS: при стоянке ≥60 с понижать частоту (перезапуск потока с большим `distanceFilter`), выход по смещению >30 м.
   Ручная пауза/продолжить.
3. **Рекордер iOS**: поля `autoPaused`, `manualPause`, `movingSeconds`, `sinceFixSec`, `gpsEnabled` заполняются так же,
   как из Android-службы (чтобы карточка записи работала без `Platform`-развилок).
4. **Разрешения**: сначала «При использовании», затем запрос «Всегда» (подсказка, как включить в Настройках, если отказано);
   `readiness.dart`: ветка iOS (геолокация «Всегда», точная геолокация, режим энергосбережения). Проверить совместимость
   `permission_handler` 12 с iOS (для `Permission.locationAlways` нужен макрос в `Podfile`/SPM: `PERMISSION_LOCATION=1`).
5. **Цель по дистанции** на iOS: расчёт в Dart; уведомление «цель достигнута» — локальное, нужен пакет
   `flutter_local_notifications` (**новая зависимость, согласовать**; без него — только значок/индикатор в приложении).
6. **Восстановление**: при старте приложения помечать оборванную сессию как «прервана» (уже есть) и добавить в лог причину
   (выгрузка, перезагрузка, ручной выход).
7. **Лог**: тот же `DebugLog`, теги `[FIX] [BEAT] [WATCHDOG] [LIFECYCLE]`, плюс статус `CLAuthorizationStatus` и признак точной геолокации.
8. **Проверки**: `flutter analyze`, юнит-тесты движка; GitHub Actions собирает `.ipa`; на iPhone — тест-прогулка 30–40 мин
   с выключенным экраном (инструкция владельцу будет отдельно).

## 4. Риски и открытые вопросы

- **Выгрузка приложения в фоне.** Режим `location` обычно удерживает приложение, но при нехватке памяти iOS может его убить.
  Это единственное серьёзное отличие от Android; измеряем реальной прогулкой.
- **Точная геолокация** (iOS 14+): пользователь может выдать «приблизительную» — трек станет бесполезным. Нужен явный запрос
  (`NSLocationTemporaryUsageDescriptionDictionary` + `requestTemporaryFullAccuracy`) и предупреждение в «готовности».
- **Бесплатный Apple ID**: подпись на 7 дней, нужно продлевать через SideStore; макс. 3 приложения (SideStore + Tropa = 2).
- **Отладка вслепую**: нет Mac/Xcode и симулятора. Вся диагностика — через `DebugLog` и кнопку «Отправить лог».
- **Версия iOS 27**: совместимость сторонних пакетов (`maplibre_gl`, `geolocator`) с новыми SDK проверяется только запуском.
- Автозапись 24/7 на iOS (CoreMotion + «значимые изменения») и компас/голос — этап 3, отдельное согласование.
